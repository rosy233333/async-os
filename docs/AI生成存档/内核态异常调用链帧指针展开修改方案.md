# 内核态异常调用链帧指针展开修改方案（仅打印 PC）

  ## Summary

  在 modules/trampoline/src/arch/riscv/mod.rs 的 slow_path_entry 异常 panic 分支（当前 117 行 if let Trap::Exception(e)）调用新增的
  dump_trap_backtrace(tf)，对内核态异常做帧指针展开，打印被打断执行流的调用链 PC 地址序列，然后照常 panic。仅打印裸地址，函数名/源码行号用
  已带调试信息的 ELF 在宿主机离线解析（addr2line）。用户态异常不展开调用链，只打印寄存器上下文。

  依据（已实测）：内核构建经 scripts/make/cargo.mk 强制 -C force-frame-pointers=yes，现有 ELF 反汇编确认标准帧布局 s0 = sp + frame_size、
  [s0-8] = ra、[s0-16] = 上一帧 s0。

  ## Key Changes

  1. 新增 modules/trampoline/src/arch/riscv/backtrace.rs，导出 pub(crate) fn dump_trap_backtrace(tf: &TrapFrame)：
      - 一律先打印上下文行：scause 异常码、stval、sepc、regs.ra/sp/s0、SPP 模式。
      - 模式判定 tf.sstatus bit 8：SPP = 0（用户态）时打印一行“用户态异常，不展开内核态调用链”并返回，不做任何栈读取；仅 SPP = 1 时展开。
      - 展开循环（上限 64 帧）：首帧 pc = tf.sepc，fp = tf.regs.s0，sp0 = tf.regs.sp；每步读 ra = *(fp - 8)、next_fp = *(fp - 16)
        （riscv64）。每次解引用前校验，任一失败立即停止，避免 panic 路径内二次缺页：
          - fp % 16 == 0（RISC-V 帧对齐）；
          - fp >= sp0 + 16 && fp < sp0 + TASK_STACK_SIZE（TASK_STACK_SIZE = 0x40000，axconfig 常量）；
          - next_fp > fp（帧链单调递增，保证终止）；
          - 当前帧 pc ∈ [_stext, _etext)（extern "C" 声明链接脚本符号，同 axhal/mem.rs 的做法）。

      - 每帧输出一行 #[nn] pc = 0x...，用 log::error!。

  2. 接线：mod.rs 中 mod backtrace;，在异常分支 panic! 之前插入 backtrace::dump_trap_backtrace(tf);。
  3. 不新增依赖；不使用用户态相关常量/逻辑，不修改链接脚本与构建系统。

  ## Test Plan

  - 构建：make A=apps/coroutine_test，确认编译通过且不影响现有功能。
  - 内核态异常：临时在某内核协程/函数注入故障指令（如对 0 地址解引用），运行后确认打印链形如 故障函数 → 调用者 → … → poll → run_task → 调
    度/ trap 入口；将每个 pc 用 riscv64-unknown-elf-addr2line -e <app>_riscv64-qemu-virt.elf -f -C <pc> 离线解析，核对函数名与源码行号。

  - 健壮性：人为破坏 s0（或制造深递归），确认在 64 帧或校验失败处截断、不触发二次异常；boot 阶段任务异常（boot_stack）也能正常展开。
  - 用户态异常：触发一次用户缺页，确认只打印寄存器上下文与“不展开”提示，不读用户内存、不崩溃。

  ## Assumptions

  - 范围仅限内核态；用户态异常仅打印上下文行，不做调用链展开（实现与测试均不涉及用户态）。
  - 只输出裸地址，内核内不做符号/行号解析；行号离线用 addr2line 对照 ELF 获取。
  - 帧指针由现有构建选项保证（force-frame-pointers=yes），不新增任何编译参数。
  - 展开始终开启（仅作用于本就 fatal 的异常 panic 路径），不加 feature 开关。
